# Проект: торговый бот для 5-минутных рынков Polymarket

Этот файл Claude читает **автоматически в начале каждой сессии**.

## Состояние

Прежняя стратегия удалена целиком (Score, Q, импульс, развороты) — по прямой
просьбе юзера. `flowbot/strategy.py` остался ЧИСТЫМ ЛИСТОМ и базой контракта:
три метода возвращают «ничего не делать».

Поверх него написана **стратегия «покупка почти-факта»** —
`flowbot/certainty.py` + `flowbot/risk.py`. Она выбирается конфигом
(`FLOW_STRATEGY=certainty`), по умолчанию выключена (`none`).

## Устройство

```

  signals.py    сырые данные: цена + книги. Производных величин НЕТ.
  engine.py     база: фиды, границы раунда, поток CLOB, главный цикл.
  trading.py    ордера, учёт позиций, сверка с биржей, расчёт, журнал.
  positions.py  сверка: биржа — источник истины.
  fills.py      разбор ответа биржи (частичный филл, отказ, UNKNOWN).
  stats.py      журнал сделок вне папки проекта.

  singleton.py  замок «один бот на рынок».
  cli.py        разбор аргументов.
```

**Журнал сделок — `~/.flowbot/trades.jsonl`, ВНЕ папки проекта.** История
обнулялась при каждом обновлении (bot16, bot18, bot20 — в каждой свой CSV с
нуля). Журнал пишет строку JSON на каждую закрытую позицию и переносит туда
всё, что стратегия положила в `Action.feat`. Только дописывается.

Настройки — `flow.env` (в .gitignore), образцы `flow.env.example` (полный,
с пояснениями) и `cert.env.example` (готовый пресет стратегии).
Тесты: `python -m pytest tests/ -q` (сейчас 202).

## Контракт стратегии с движком

```python
act = strategy.on_tick(snapshot)      # каждое событие книги
  -> Action(NONE)                     # ничего не делать
  -> Action(BUY,  outcome="Up"|"Down", limit_price=ask, size_usdc=...)
  -> Action(SELL, sell_idx=leg.idx, sell_outcome=..., limit_price=bid)

strategy.record_entry(...)            # движок сообщает о факте покупки
strategy.record_sell(...)             # и о факте продажи
strategy.reset_round()                # начало нового окна
```

`Snapshot` несёт только СЫРОЕ: время, остаток окна, цену монеты, таргет,
bid/ask обеих сторон, якорь Polymarket, флаг `entries_paused`, историю цены
(`price_hist`), уровни книги (`up_levels`/`down_levels`) и возраст книги
(`book_age_s`). Волатильность, скорости и структуру книги стратегия считает
сама. Движок ещё зовёт `record_settle(leg, payout, pnl, t)` по расчёту раунда
— без этого дневной риск слеп: `record_sell` знает только про позиции,
которые закрыли сами.

## Стратегия «покупка почти-факта» (`certainty`)

**Арифметика, из которой следует всё остальное.** $50 по 0.98 = 51.02 шэра:
выигрыш +$1.02, проигрыш −$50. Порог безубытка = 50/51.02 = **98.00%, ровно
цена контракта**. Это тождество, а не совпадение. Значит:

* **отсеивание сделок само по себе не улучшает матожидание** — убирает
  выигрыши и проигрыши в одной пропорции. Каждый фильтр обязан быть
  ПРЕДСКАЗАТЕЛЬНЫМ (подтверждать, что раунд решён), а не просто осторожным;
* **источник прибыли ровно один — премия за определённость**: шаг цены целый
  цент, ММ не котируют 0.999, поэтому раунд, решённый на 5σ (истинная
  вероятность 0.9999997), продолжает стоить 0.98;
* **одна потеря съедает 49 выигрышей подряд.**

Центральная величина — запас в сигмах `z = (цена−таргет)/(σ√t)` в пользу
покупаемой стороны. При z=2.05 модель даёт ровно 0.98 = ровно безубыток.
Вход разрешён от z≥4 (`CERT_Z_MIN`).

Остальные 8 факторов отвечают на вопрос «можно ли верить этому z» и дают
единую оценку риска 0..100 (`risk.assess`, веса в сумме 100): запас 30,
скорость 15, скачок 13, режим волатильности 12, глубина 10, спред 8, уход
бидов 5, пила 4, расхождение с якорем 3. Вход при score ≤ `CERT_RISK_MAX`.

Отдельно — ЖЁСТКИЕ запреты (не баллы, а «нельзя»): нет цены/таргета/σ/ask,
цена вне 0.960–0.985, спред > 5¢, глубины ПО НАШЕЙ ЦЕНЕ меньше ступени,
до расчёта <10с или >120с, цена старше 2с, книга не менялась >5с.

Лестница 10/10/10/20 набирает **вверх по уверенности, а не вниз по цене**:
порог ужесточается на 3 за ступень, запасу нельзя просесть больше чем на
0.3σ, иначе набор прекращается насовсем в этом раунде.

Аварийный выход — **не стоп по цене**: процент проваливается до 0.50 и
возвращается на 0.98 за секунду. Выходим по состоянию рынка (запас < 2.5σ
или запас < 1.5× худшей наблюдённой секунды) и только после 5 тактов подряд
за ≥1.5с.

## Ключевая математика (осталась верной, кода больше нет)

```
P(Up) = Φ( (цена − таргет) / (σ · √время) )
```

* **Чувствительность** процента к движению цены = `φ(z)/(σ√t)`. Максимальна
  на таргете, падает экспоненциально. Далеко от таргета проценты не
  реагируют на скачки — раунд уже решён.
* **«Далеко» измеряется в σ√t, а не в долларах.** 3σ это $38 при тихом
  рынке и $255 при разогнанном. Любой фиксированный долларовый порог неверен.
* **EV покупки при удержании до расчёта = `p − ask`.**

## Что выяснено про РЫНОК (не переоткрывать)

Это факты про площадку и исполнение. Они переживают любую смену стратегии.

* **Спред 5 центов, не 1.** Up 0.89/0.94 и Down 0.06/0.11 в сумме дают 1.00
  с обеих сторон — это ОДНА книга с двух сторон. «Купить Up по 0.94» и
  «продать Down по 0.06» — одна заявка. Спред НЕ константа: 5¢ около
  таргета, 1¢ на решённом раунде с глубиной 1500+.
* **Опережение перед Polymarket ~288 мс** (`prices["polymarket"]` — якорь
  уровня в `fast_monitor`, остальные биржи дебиасятся относительно него,
  поэтому разрыв «наша цена − pm» это чистое опережение).
* **ЭТО ОПЕРЕЖЕНИЕ СТОИТ МЕНЬШЕ СПРЕДА.** `Δp = φ(z)·√(0.288/t_ост)` — 1.35¢
  при 250с до расчёта, 1.75¢ при 150с, 2.76¢ при 60с, 3.91¢ при 30с (при
  z=0), и 0.2-0.5¢ на |z|=2. Круг по спреду стоит 1-5¢. **Потолок
  преимущества по информации ниже стоимости входа-выхода на большей части
  раунда.** Любая новая стратегия обязана это учитывать: «запас 3¢» в
  середине раунда почти всегда ошибка измерения σ, а не возможность.
* **Четыре изученных прибыльных кошелька — маркет-мейкеры**, не угадыватели
  направления: только BUY, обе стороны 50/50, пара Up+Down за $0.977 при
  выплате $1. Бот, переходящий спред, — их клиент.
* **σ по MAD занижает σ для Φ в 1.4-1.6 раза** на скачковых данных: Φ нужна
  СКО, а MAD игнорирует хвосты — то есть ровно то, чем крипта и движется.
  σ, вшитая в книгу (`σ_book = d / (Φ⁻¹(ask)·√t)`), даёт 2-4 против 0.9.
* **σ в тихое воскресенье ~0.9 $/√с**, весь раунд решается в пределах ±$11
  от таргета. В рабочие дни в разы больше.

## Что выяснено про ИСПОЛНЕНИЕ (всё это в коде и работает)

* **РАЗМЕР ОРДЕРА — ТОЛЬКО ЦЕЛЫМИ ШЭРАМИ.** Polymarket отвергает покупку,
  если сумма в USDC длиннее двух знаков: 0.57 × 1.76 = $1.0032 -> 400
  `invalid amounts`. Цена всегда в целых центах, поэтому два знака
  гарантирует только целое число шэров (`btc_bot.util.whole_shares`).
* **Округление шэров ВНИЗ опускало каждый ордер под доллар**: $1.00/0.53 =
  1.8867 → 1.88 → $0.9964. Сравнивать надо НЕОКРУГЛЁННОЕ произведение.
* **РАЗМЕР ПРОДАЖИ УСЕКАЕТСЯ ВНИЗ, НИКОГДА НЕ ОКРУГЛЯЕТСЯ.** Позиция
  0.067795 шэра уходила в ордер как 0.07 = 70000 сырых против баланса
  67795 -> 400 `not enough balance`. Продать больше, чем лежит, нельзя.
* **DRY-RUN НЕ ПРОВЕРЯЕТ ПУТЬ ОРДЕРА.** Симулированный трейдер всегда
  отвечает полным филлом, поэтому разбор ответа биржи (`flowbot/fills.py`)
  надо тестировать отдельно: FAK даёт нулевой и частичный филл, продажа при
  пустой книге уходила по 0.00, пол цены принимался и игнорировался.
* **БОТ НЕ ЗНАЛ, ЧЕМ ВЛАДЕЕТ.** Учёт по своим записям расходится с биржей
  тремя способами: таймаут ордера, ответ разобран как отказ при фактическом
  филле, частичная продажа. Лечится только сверкой (`flowbot/positions.py`,
  раз в `FLOW_RECONCILE_S`). Биржа — источник истины. Непонятный ответ =
  None («не знаю»), НЕ ноль, иначе бот выбросит настоящую позицию.
* **ОСТАТОК ОТ ЗАКОНЧИВШЕГОСЯ РАУНДА НЕ ПРОДАЁТСЯ, А ЗАБИРАЕТСЯ (Redeem).**
  Книги того окна больше нет, «Market Sell» отвечает `balance: 0`.
* **МОЛЧАЛИВЫЙ ОТКАЗ ТОРГОВАТЬ — самый коварный.** У запроса к бирже нет
  своего таймаута, поэтому повисший ордер оставлял `busy=True` навсегда:
  строки состояния идут, а сделок нет и причина нигде не названа. Отсюда
  `FLOW_ORDER_TIMEOUT_S` и сторож. При таймауте позицию НЕ записываем.
* **ПАУЗА ПОСЛЕ ОТКАЗА НЕ ДОЛЖНА ТРОГАТЬ ВЫХОД.** Вход отложить можно,
  выход — никогда. Но детерминированный отказ («не хватает баланса») иначе
  повторяется 10 раз в секунду: отсюда `FLOW_MAX_SELL_FAILS`.
* **Запись `--record` пишет ~10 ГБ в сутки.** Такт случается на каждом
  событии книги, а не по таймеру.
* **ЗАДЕРЖКА ОРДЕРА — 310 мс, А НЕ 45.** Измерено `pingorder.py` на боевом
  сервере (Vultr, RTT до Cloudflare **1.7 мс**): от решения до ответа биржи
  медиана **310 мс**, разброс всего ~7 мс. Такая стабильность означает не
  сеть, а фиксированную стоимость сервера Polymarket — проверка подписи,
  баланса, матчинг. **Убрать её нельзя ничем: ни переездом, ни кодом.**
  Стояло 45 → симуляция была оптимистичнее боя в 6.7 раза.
  Раскладка: сеть ~1 мс, подпись 7 мс, Polymarket ~300 мс.
* **ПЕРВЫЙ ОРДЕР НА НОВЫЙ ТОКЕН ДОРОЖЕ НА 98 мс.** Клиент биржи при первой
  подписи ходит в сеть за `neg_risk`/`tick_size`. Токены меняются каждые 5
  минут, поэтому это платила первая ступень лестницы В КАЖДОМ раунде.
  Лечится предподписанием (`LiveTrader.presign_window`), которое теперь
  зовётся из `TradingEngine._enter_window`. Ключ заготовки — (токен, цена,
  размер), и размер обязан считаться тем же `whole_shares`, иначе заготовка
  не найдётся НИКОГДА и работа пропадёт молча (есть тест).
* **Зонд меряет боевой путь, не тратя денег** (`pingorder.py`): настоящий
  подписанный FAK по цене 0.01 при рынке 0.98 — продавца нет, филла нет,
  путь пройден целиком. НО размер обязан давать **≥ $1**: минимум ордера
  площадки, иначе `invalid amount ... min size: 1` ещё до матчинга. Отказ
  биржи — это тоже валидный замер, ответ идёт тем же путём.

## Правила работы с этим проектом

1. **Не подбирать пороги на глаз.** Здесь уже дважды делались выводы на
   9-20 наблюдениях, и оба разворачивались от пары случаев. Есть `replay.py`
   и журнал сделок — пользоваться ими.
2. **DRY_RUN=true по умолчанию.** Реальные деньги — только после сотен
   раундов на симуляции.
3. **Все `*.env` в .gitignore** — там `PRIVATE_KEY`/`FUNDER`. В репозитории
   только `*.env.example` с пустыми кредами.
4. **Новый параметр добавляется вместе с кодом, который его читает.**
   Конфиг уже однажды зарос ключами, которые ничего не делали.
5. **Молчаливо неверная настройка хуже ошибки.** Каждый порог стратегии
   проверяется в `FlowConfig.validate()`: неверный порог означает бота,
   который не торгует и не говорит почему.
6. Русские комментарии в коде — норма для этого проекта.

## Что дальше

Инфраструктура готова и проверена. Стратегия написана и покрыта тестами
(202), но **на реальных данных не проверена ни разу**.

**ДАННЫХ ПО-ПРЕЖНЕМУ НЕТ.** Запись рынка (`--record`) не запускали ни разу,
поэтому все пороги в `cert.env.example` — рассуждения, а не измерения. Это
ровно то, что правило №1 запрещает оставлять как есть.

Порядок действий:

1. `python trader.py --env-file cert.env --record market.jsonl` — собрать
   запись параллельно с наблюдением за dry-run.
2. `python replay.py market.jsonl --strategy certainty` — посмотреть, что
   стратегия делала бы на этой истории.
3. `python replay.py market.jsonl --strategy certainty --sweep z-min 3 4 5 6`
   — и так по каждому порогу. Ключи перебора перечислены в `SWEEPS`.
4. Только потом — `--live`, и только с деньгами, которые не жалко.

**Чего ЖДАТЬ от результата.** Стратегия по построению зарабатывает $1 на
раунд и теряет $50. При 50 сделках в день и одной потере в неделю она в
нуле. Проверять надо не «сколько заработала», а **сколько раз запас z был
больше 4, а раунд всё равно перевернулся** — это и есть та величина, ради
которой всё написано.
