# Проект: торговые боты для 5-минутных рынков Polymarket

Этот файл Claude читает **автоматически в начале каждой сессии**. Всё, что
здесь написано, не нужно пересказывать заново.

## Что это за проект

Боты на Up/Down рынки Polymarket (5 и 15 минут, BTC/ETH/SOL/XRP). Раунд:
в начале фиксируется таргет (`openPrice`), в конце цена сравнивается с ним.
Выигравший шэр платит **ровно $1**, проигравший — $0. Цена шэра и есть
оценка вероятности.

## Устройство

```
dashboard.py       одно окно, 4 панели (панели 1-3 показывают, 4-я торгует)
├─ pm_view.py      зеркало Polymarket
├─ fast_monitor.py цена с 7 бирж, опережает Polymarket на ~300мс
├─ book_monitor.py книга заявок Up/Down
└─ jump_trader.py  ЕДИНСТВЕННЫЙ, кто торгует (flowbot/jump*.py)

replay.py     прогон записи через стратегию с любыми порогами
features.py   измерение предсказательной силы признаков (IC)
backtest.py   бэктест СТАРОЙ стратегии по историческому API
```

Настройки — `flow_jump.env` (в .gitignore). Правила — `JUMP.md`.
Тесты: `python -m pytest tests/ -q` (сейчас 204).

## Ключевая математика

```
P(Up) = Φ( (цена − таргет) / (σ · √время) )
```

Из неё следует всё остальное:

* **Чувствительность** процента к движению цены = `φ(z)/(σ√t)`. Максимальна
  на таргете, падает экспоненциально с расстоянием. Поэтому далеко от
  таргета проценты не реагируют на скачки — раунд уже решён.
* **«Далеко» измеряется в σ√t, а не в долларах.** 3σ это $38 при тихом
  рынке и $255 при разогнанном. Любой фиксированный долларовый порог неверен.
* **Нужный скачок линеен по σ.** Тот же эффект: $4 при σ=0.9, $28 при σ=6.
* **EV покупки при удержании до расчёта = `p − ask`.** Ровно это считает
  `JUMP_MIN_EDGE_CENTS`.

## Что уже выяснено (не переоткрывать)

* **Спред 5 центов, не 1.** Up 0.89/0.94 и Down 0.06/0.11 в сумме дают 1.00
  с обеих сторон — это ОДНА книга, показанная с двух сторон. «Купить Up по
  0.94» и «продать Down по 0.06» — одна заявка.
* **Лестница добора — мартингейл.** На реальных данных ступени 0-2 дали
  +$41, третья −$27.55. Соотношение риск/прибыль против нас: выигрываем по
  50¢ часто, проигрываем по $11 редко. Потолки обязательны.
* **σ в тихое воскресенье ~0.9 $/√с**, весь раунд решается в пределах ±$11
  от таргета. В рабочие дни в разы больше — пороги подстраиваются сами
  (`JUMP_ADAPTIVE`).
* **Опережение перед Polymarket ~288 мс** (видно в логе как `pm288`).
  Считать его надо от `fast_monitor.prices["polymarket"]`, а НЕ от таргета
  раунда — это разные вещи, и путаница здесь ломает любую модель.
* **Четыре изученных прибыльных кошелька — маркет-мейкеры**, не угадыватели
  направления: только BUY, обе стороны 50/50, пара Up+Down за $0.977 при
  выплате $1. Наш бот — их клиент: он переходит спред, они его собирают.

## Правила работы с этим проектом

1. **Не подбирать пороги на глаз.** Здесь уже дважды делались выводы на
   9-20 наблюдениях, и оба разворачивались от пары случаев. Есть `replay.py`
   и `features.py` — пользоваться ими.
2. **`--split` обязателен.** Признак, не переживший вторую половину выборки,
   был подгонкой.
3. **DRY_RUN=true по умолчанию.** Реальные деньги — только после сотен
   раундов на симуляции.
4. **Один бот на рынок.** Вторая копия ведёт свою лестницу, риск
   складывается. Есть замок (`flowbot/singleton.py`), обойти можно только
   `--allow-multiple`.
5. **Все `*.env` в .gitignore** — там поля PRIVATE_KEY/FUNDER. В репозитории
   только `flow_jump.env.example` с пустыми кредами.
6. Русские комментарии в коде — норма для этого проекта, продолжать так же.
