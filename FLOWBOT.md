# flowbot — единый трейдер: цена + книга (5-мин BTC на Polymarket)

`flowbot` объединяет два твоих монитора в **одну автоматическую систему**,
которая торгует ровно по описанной логике:

* **«Бот 1»** — `fast_monitor.py` — даёт **цену BTC** чуть раньше, чем её
  покажет Polymarket (консенсус 7 бирж + наукаст). Отсюда система берёт
  **резкое движение цены**.
* **«Бот 2»** — `book_monitor.py` — даёт **книгу заявок** рынка Up/Down 5m
  (все заявки, лучшие bid/ask по обеим сторонам, поток сделок). Отсюда
  система видит **«проценты» Up и Down** и куда толпа двигает цену.

Система **непрерывно** мониторит оба сигнала и на резком движении открывает
сделку, держит её, пока движение идёт, и защищается на развороте.

> ⚠️ **Это экспериментальный торговый софт.** По умолчанию — `DRY_RUN`
> (симуляция, без реальных ордеров). Пороги ниже — разумная стартовая точка,
> их НУЖНО подбирать под себя (см. «Тюнинг»). Торговля предиктивными рынками
> — реальный риск потерять деньги. Начинай в dry-run, ставь маленькую сумму,
> не рискуй тем, что не готов потерять.

## Как это работает — коротко

```
 биржи (Coinbase/Kraken/Bitstamp/Pyth/Binance/OKX/Bybit) + якорь Polymarket
        │                                                     │
        ▼   fast_monitor.Consensus + Nowcast + VolEstimator   │
   PriceEngine ──► burst_z (всплеск скорости в σ), move_bps    │
        │                                                      │
        │           CLOB Market WebSocket (книга Up/Down)      ▼
        │                    BookEngine ──► best bid/ask, доскачковый ask,
        │                                   поток заявок (имбаланс)
        ▼                         ▼
      ┌───────────── FlowStrategy (чистая логика) ─────────────┐
      │  вход / удержание / выход / разворот                   │
      └───────────────────────────┬────────────────────────────┘
                                   ▼
                      FlowEngine + LatencyModel
             (исполнение с реалистичным пингом Цюрих→Polymarket)
                                   ▼
                    LiveTrader / DryRunTrader (py-clob-client)
```

## Логика сделок (как ты и просил)

### Вход
Когда по цене BTC произошло **резкое движение** (всплеск скорости
`|burst_z| ≥ FLOW_ENTRY_BURST_Z` в σ и абсолютно `≥ FLOW_ENTRY_MIN_MOVE_BPS`
б.п.) — покупаем **ту сторону, куда пошла цена**: вверх → `Up`, вниз → `Down`.

Вход только если у «процента» есть **запас двигаться в нашу сторону**:
ask стороны в диапазоне `[FLOW_ENTRY_PRICE_MIN, FLOW_ENTRY_PRICE_MAX]`
(по умолчанию `0.20…0.90`).

Ставка — **$1** (`FLOW_STAKE_USDC`). Лимита на число ставок в окне нет:
после выхода можно снова войти на новом всплеске.

### Предосторожность №1 — не успели купить по доскачковому проценту
Если книга уже поехала (например, `Down` был **56**, а сейчас дороже),
система **догоняет**, но не дороже, чем `доскачковый ask + FLOW_CHASE_CENTS`
(по умолчанию **2 цента** → 57–58). Ушло дальше — **вход пропускаем**
(в логе: «книга ушла — вход пропущен»). «Доскачковый» ask — это лучший ask
`FLOW_CHASE_LOOKBACK_S` секунд назад.

### Удержание
Держим позицию, пока **одновременно**:
1. **движение BTC продолжает идти в нашу сторону** (`burst_z` в нужном
   направлении ≥ `FLOW_HOLD_BURST_Z`), и
2. **«процент» купленной стороны растёт** (текущий bid не откатился от
   своего пика больше, чем на `FLOW_TOKEN_RETRACE_EXIT`).

Как только одно ломается — и это держится `FLOW_FADE_GRACE_S` (защита от
одного шумного тика) — **выходим** (продаём по биду).

Дополнительно: если ушли **глубоко в деньги** (`bid ≥ FLOW_TAKE_PROFIT_PRICE`,
деф. 0.95) — держим до расчёта (сеттл платит $1/шт). В конце окна
(`≤ FLOW_SETTLE_HOLD_S`) выигрышную позицию держим до сеттла, проигрышную —
продаём, чтобы спасти кэш.

### Предосторожность №2 — резкий разворот
Если **после** покупки цена **резко и сильно** пошла в противоположную
сторону (`|burst_z| ≥ FLOW_FLIP_BURST_Z`, деф. 3.5, против нас) — система
**сразу берёт противоположную сторону на $3–4** (`FLOW_FLIP_SIZE_USDC`), а
свою **продаёт как можно раньше**. Порог разворота выше обычного входа,
поэтому флип срабатывает только на действительно сильном движении.

## Пинг (VPS в Цюрихе) — реалистичная задержка

Между тем, как **мы** увидели движение (по биржам, опережающим сайт), и тем,
как наш ордер реально ляжет в матчинг Polymarket, проходит время: сеть
Цюрих→США + подпись ордера + обработка. `flowbot` это **учитывает**:

* на старте **меряет реальный RTT** до `clob.polymarket.com` (TCP-handshake)
  и печатает его;
* если замер недоступен или задан `--ping-ms` — берёт ориентир
  Цюрих→Polymarket (инфраструктура в US-East): **RTT ≈ 90 мс**
  (`FLOW_ASSUMED_RTT_MS`), плюс обработка ордера `FLOW_ORDER_PROCESS_MS` (45 мс);
* в **dry-run** исполнение **задерживается** на реалистичный пинг, и цена
  берётся уже на момент «прилёта» ордера — симуляция честно показывает
  проскальзывание;
* тот же пинг работает в «догоне» (предосторожность №1): если за время полёта
  книга ушла дальше 1–2 центов — вход пропускается (в dry-run видно как
  «ask … > лимит … — книга ушла за пинг»).

Типичные наземные RTT из Цюриха: до восточного побережья США ~85–95 мс, до
западного ~150 мс. Задай `--ping-ms 90` (или свой замер `ping clob.polymarket.com`
с самого VPS), чтобы зафиксировать величину.

## Установка и запуск

Требуется Python 3.10+.

```bash
pip install -r requirements.txt      # websockets + requests + py-clob-client(+v2)
```

**Симуляция (начни отсюда):**

```bash
python -m flowbot.run --dry-run --ping-ms 90
# или через пресет:
python flow_trader.py --env-file flow_btc.env
```

**Реальная торговля** (заполни креды в `flow_btc.env`, как в `bot1.env`:
`PRIVATE_KEY`, `FUNDER`, `SIGNATURE_TYPE=3`), затем:

```bash
python -m flowbot.run --live --ping-ms 90
```

### CLI

```
python -m flowbot.run [опции]
  --dry-run / --live      симуляция (деф.) / реальные ордера
  --coin {btc,eth,sol,xrp,doge}   монета (деф. btc)
  --stake FLOAT           ставка на вход, USDC (деф. 1)
  --flip-size FLOAT       разворотная ставка, USDC (деф. 3.5)
  --entry-z FLOAT         порог всплеска для входа в σ (деф. 2.5)
  --ping-ms FLOAT         зафиксировать RTT, мс (иначе меряем; ориентир 90)
  --hours FLOAT           сколько работать (деф. 24)
  --env-file PATH         загрузить пресет .env
  --log-level LEVEL       DEBUG / INFO / WARNING
```

## Что видно в логе

Раз в секунду печатается строка состояния (система «мониторит без остановки»):

```
t-176s | BTC 63,949 nc=63,951 z=+0.83 (+0.83б.п.) | Up 0.91/0.92(+1.00) Down 0.08/0.09(+0.43) | поз — | нет резкого движения
```

* `BTC … nc=…` — живая цена и наукаст (быстрый слой бирж);
* `z=… (…б.п.)` — всплеск скорости в σ и абсолютное движение;
* `Up bid/ask(поток)` и `Down bid/ask(поток)` — «проценты» обеих сторон и
  имбаланс потока заявок (>0 — давят на покупку этой стороны);
* `поз` — текущая позиция; в конце — причина решения.

Сделки печатаются отдельно (`>>> ENTER/EXIT/FLIP`, `КУПЛЕНО`, `ПРОДАНО`,
`СЕТТЛ`) и пишутся в CSV `FLOW_TRADE_LOG_CSV` (по умолчанию `flowbot_trades.csv`).

## Справочник конфигурации

Всё задаётся в `flow_btc.env` (или через окружение). Ключевое:

| Переменная | Деф. | Смысл |
|---|---|---|
| `DRY_RUN` | `true` | `false` = реальные ордера |
| `FLOW_STAKE_USDC` | `1.0` | ставка на обычный вход |
| `FLOW_FLIP_SIZE_USDC` | `3.5` | разворотная ставка ($3–4) |
| `FLOW_MOMENTUM_HORIZON_S` | `1.0` | окно измерения всплеска |
| `FLOW_ENTRY_BURST_Z` | `2.5` | порог «резкого движения» в σ |
| `FLOW_ENTRY_MIN_MOVE_BPS` | `1.0` | абсолютный пол движения, б.п. |
| `FLOW_MIN_SIGMA_BPS` | `0.2` | пол волатильности (гасит ложные всплески на прогреве) |
| `FLOW_ENTRY_PRICE_MIN/MAX` | `0.20/0.90` | диапазон «процента» для входа |
| `FLOW_CHASE_CENTS` | `0.02` | догон: макс. переплата над доскачковым ask |
| `FLOW_CHASE_LOOKBACK_S` | `1.5` | «доскачковый» ask = ask столько сек назад |
| `FLOW_MIN_HOLD_S` | `0.4` | не выходим первые доли секунды |
| `FLOW_HOLD_BURST_Z` | `0.3` | движение «ещё идёт», пока z в нашу сторону ≥ это |
| `FLOW_FADE_GRACE_S` | `0.8` | выход только если фейд держится столько |
| `FLOW_TOKEN_RETRACE_EXIT` | `0.03` | выход, если % откатился от пика на это |
| `FLOW_TAKE_PROFIT_PRICE` | `0.95` | глубоко в деньгах → держим до расчёта |
| `FLOW_SETTLE_HOLD_S` | `6.0` | в конце окна выигрыш держим до сеттла |
| `FLOW_FLIP_ENABLED` | `true` | включить разворот |
| `FLOW_FLIP_BURST_Z` | `3.5` | порог разворота (против нас) в σ |
| `FLOW_FLIP_MIN_MOVE_BPS` | `2.0` | абсолютный пол разворотного движения |
| `FLOW_FLOW_CONFIRM` | `true` | мягкое вето по потоку заявок |
| `FLOW_FLOW_VETO` | `-0.6` | не входим, если поток стороны < это |
| `FLOW_PING_MS` | (пусто) | зафиксировать RTT; пусто = мерить вживую |
| `FLOW_ASSUMED_RTT_MS` | `90.0` | ориентир RTT Цюрих→Polymarket |
| `FLOW_ORDER_PROCESS_MS` | `45.0` | подпись + матчинг сверх сети |
| `FLOW_SIMULATE_LATENCY` | `true` | в dry-run задерживать филлы на пинг |

## Тюнинг

* **Слишком много входов** → подними `FLOW_ENTRY_BURST_Z` (напр. 3.0–3.5) и/или
  `FLOW_ENTRY_MIN_MOVE_BPS`.
* **Рано выходит** → подними `FLOW_FADE_GRACE_S` и `FLOW_TOKEN_RETRACE_EXIT`,
  снизь `FLOW_HOLD_BURST_Z`.
* **Часто «книга ушла»** (не успеваем войти) → увеличь `FLOW_CHASE_CENTS` до
  0.03, но помни: чем больше догон, тем хуже цена входа.
* **Флип бьёт слишком легко/редко** → крути `FLOW_FLIP_BURST_Z`.
* Проверяй результаты по `flowbot_trades.csv` за много окон, прежде чем идти
  в `--live`.

## Архитектура

```
flowbot/
  config.py     конфигурация (пороги, размеры, пинг) из env/.env
  latency.py    модель пинга: замер RTT + симуляция задержки исполнения
  signals.py    PriceEngine (всплеск скорости) + BookEngine (книга/поток)
  strategy.py   ЧИСТАЯ логика вход/удержание/выход/разворот (юнит-тесты)
  engine.py     async-движок: фиды + книга + стратегия + трейдер
  run.py        CLI
flow_trader.py  обёртка запуска из корня
flow_btc.env    пресет BTC
tests/
  test_flow_strategy.py   тесты чистой стратегии (без сети)
  test_flow_engine.py     оффлайн-тесты движка (вход/выход/сеттл/флип)
```

Логика решений (`strategy.py`) отделена от I/O, поэтому вся стратегия
покрыта тестами без сети и без ключей:

```bash
python -m pytest tests/test_flow_strategy.py tests/test_flow_engine.py -q
```

`flowbot` переиспользует существующие модули: фиды цены из `fast_monitor.py`,
книгу из `book_monitor.py`, трейдер/баланс из `btc_bot/` — ничего не
дублируя.
